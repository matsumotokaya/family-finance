# 月次カード確認・LINE下書き作成の手順

銀行の月次更新は末尾の「銀行スクリーンショットの月次更新」も参照する。

確認日: 2026-10-05

## 目的と対象

未来さんの家族カード（末尾0406）の月ごとの利用を確認し、本人に明細確認・精算を依頼する。末尾1205とルミネカード末尾0021は対象外。VIEW’s NETのカード選択は親カード1205のままで、明細中の0406を抽出する。

家計ツール: https://family-finance-bay-one.vercel.app
取り込み: https://family-finance-bay-one.vercel.app/ingest
対象月の確認: `/pending/YYYYMM`
LINE参照先: 「経費精算（2）」の既存トーク。参加者・過去の明細共有リンクを確認してから履歴を読む。

## 1. ログインと対象月の確認

1. ユーザーがChromeでVIEW’s NETにログインする。開始画面は https://www.viewsnet.jp/V0100/V0100_004.aspx?sv=w01 。既存のログイン済みタブを使い、Chromeのプロファイルを決め打ちしない。
2. 「ご利用明細照会」→「請求予定の明細」を開く。
3. セッション切れならユーザーに再ログインを依頼する。認証情報を手順書に記録しない。
4. 対象は利用日の年月。サイトの「2026年10月」等は請求月なので、利用月とは区別する。

## 2. 全ページを読む

1. 未確定明細の表を各ページから取得する。確認時は1ページ10件で、「次へ」がなくなるまで進む。
2. 利用年・月日・カード末尾・店舗・金額・支払方法を保持する。同額・同店舗・同日の複数取引を勝手に1件にまとめない。
3. 末尾0406かつ対象月の利用だけを抽出する。翌月利用は別集計にする。
4. 未確定画面にはCSV/PDFボタンがなかった。確定画面には「明細CSVダウンロード」「明細PDFダウンロード」がある。毎回画面で確認する。
5. 月初の利用が未確定一覧から消えている場合、最新の確定請求明細も確認する。今回、10月請求明細の末尾に9月1〜4日の0406利用が7件あった。
6. 確定画面ではカード番号が明細ごとの列ではなく「対象カード」の区切り行に表示される。区切り行のカードを引き継いで読み、別カードを混ぜない。
7. 表示中の対象月開始位置から最終ページまで読む。開始ページより前にも対象月がある可能性があれば前ページを確認する。

## 3. 取り込みと検証

1. 対象月の件数・金額を、確定分と未確定分に分けて計算する。
2. `/ingest` →「🕒 未確定貼付」に表を貼り付け、「取り込む」を押す。ユーザーから対象データと取り込み先への更新依頼があることを確認する。
3. 確定表をこの貼付形式に変換する場合は、日付・0406・店舗・金額を原本から転記し、実際の支払方法を保持する。表の形式は以下。金額を2行分加算しない。

```text
2026
09/01	****-****-****-0406	店舗名	16500
(16500)				ショッピング１回払い
```

4. 同一取引の再取り込みは内容ベースIDで重複排除される。「認識件数」「新規件数」「既知件数」を確認する。処理中には再送信しない。
5. `/pending/YYYYMM` を開いて、対象0406の件数・合計・明細日付が原本と一致することを確認する。除外操作がある場合は全明細合計と予算対象額を区別する。
6. 反映後のスクリーンショットを保存する。

### 現状の制約

`/pending` は家計側に取り込んだ確定明細と一致する取引を消し込む。確定表から月初利用を貼付すれば現時点の月次確認には使えるが、後日その確定CSVを取り込むと表示から消える可能性がある。月全体の利用を恒久的に残す機能ではない。これを説明し、必要なら別途表示ルールを変更する。確定分を未確定と誤説明しない。

## 4. LINEの過去の文脈を読む

1. iPhoneミラーリングを接続・再開する。iPhoneの使用中はロックが必要。
2. LINEのトーク一覧から「経費精算（2）」を開く。2026-10-05時点では一覧を少し下にスクロールすると見つかった。
3. 直近の共有URLと、前月の精算・予算・支払方法に関するやり取りを読む。ミラーリングではアクセシビリティにトーク本文が出ないためスクリーンショットで確認する。スクロールはscrollを使う。
4. 文脈: 本人に明細を確認してもらい、その後キャッシュ口座へ振り込む案内がある。医療費・子供関連・日用品などが混在する。過去には個人予算4万円をなくす話、カード利用停止、必要な支払いを夏弥さんのカードに移す話もある。過去の発言だけで現在の合意を断定せず、ユーザーの最新指示を優先する。
5. アプリの基準額4万円だけを根拠に責める文面を自動生成しない。

## 5. 下書きをユーザーに提示して終了

件数・合計・対象月URL・確認依頼を含め、過去の文体とユーザーの意図に合わせる。説明が必要な項目はコメント・除外の依頼を添える。医療費等の扱いや購入済み品は、ユーザーから聞いた事実のみを使う。

タスクはこのチャットに文案を提示したところで終了する。LINEは過去のやり取りを読む用途だけに使い、入力欄への文字入力・貼り付け・送信は行わない。ユーザーが文案をコピーし、自分でLINEへ送る。文案のURLはコピーしやすい通常のURLで記載する。

2026-10-05にユーザーから「LINEへの文字入力は無し、このチャットボックスに文案を提案するだけ」と運用を変更する指示があった。今後の月次タスクではこの方針を守る。

### 文案の例（2026年9月）

```text
9月分のカード明細を更新しました。
32件・67,470円です。

https://family-finance-bay-one.vercel.app/pending/202609

こちらの確認をお願いします！
医療費はしょうがないとしても、このカードは基本使わないようにして、日用必需品は僕のカードで依頼して買うということでお願いします。（子供用包丁と洗剤は言い忘れていましたが購入済みです）
```

この文例の金額・件数・購入済み品は当月だけの情報。翌月は再確認し、前月の具体的事実をそのまま流用しない。

2026年9月、0406: 確定7件22,134円 + 未確定25件45,336円 = 32件67,470円。2026-10-05に貼付取り込みで新規32件を追加し、`/pending/202609` の表示を確認済み。10月の未確定6件6,485円と1205の明細は今回の取り込みから除外。

## 銀行スクリーンショットの月次更新

1. ユーザーから対象年月と銀行画像を受け取る。今回の赤い明細は三菱UFJ、緑はりそな。画像内の年月・銀行識別を照合する。
2. `/ingest` の「🏦 銀行スクショ」から画像を選択し「AIで読み取る」を実行する。抽出結果は1口座なので、銀行を混ぜず、口座ごとに取り込む。同じ銀行の連続スクショはまとめて選択できる。
3. 保存前に全行の日付、入出金、金額、摘要、残高を原画像と照合する。同日の取引順にも注意する。残高チェックOKだけで正しいと判断しない。前後の残高と取引額の連鎖を検算する。
   口座名も必ず照合する。今回、りそな画像を三菱UFJと誤判定した。編集できない画面の場合は保存せず、原画像を保持した別ファイルに、ユーザーが指定した銀行名を画像外の余白へ補足して再抽出する。銀行名以外の取引内容を変更しない。
4. 画像に対象月以外の明細が含まれていれば、原画像を残したまま対象月部分だけを切り出してアップロードする。切り出した画像を目視し、年月と全取引が残っていることを確認する。銀行の取引IDは口座・日付・抽出内の連番なので、画像範囲が変わると重複排除が保証されない。
5. りそなの画像には残高がないことがある。残高を推測して登録しない。画面の月別入出金合計と明細の合計を照合する。
6. 「この内容で確定して保存」を押し、保存成功の表示を確認する。読み取り内容に誤りがあれば保存せず、正しい内容を入力できる方法を確認する。
7. `/YYYY-MM` の家計ダッシュボードで銀行明細への反映を確認する。カードの `/pending/YYYYMM` とは別の画面。
8. 原画像は `bank/YYYYMMDD/`（三菱UFJ）と `bank/YYYYMMDD-risona/` に保存して後日の照合に使う。Web取り込みとローカルJSON更新を同じ取引に二重適用しない。
9. スクショに月全件が写っているか、別途確認する。画像だけで月の完全性を断定しない。今回のUFJ画像の最終表示は9月25日、りそなは9月30日。

今回の原画像: `IMG_2553.PNG`（三菱UFJ・9月7〜25日7件、入金512,905円、出金219,000円、最終表示残高2,123,219円）、`IMG_2554.PNG`（りそな・9月30日のローン2件、8,089円と107,321円、9月合計115,410円。8月の明細も写っている）。

2026-10-05の銀行更新結果: 両銀行の計9件をWeb取り込みで保存し、`/2026-09` の表示を確認した。KYASHの34,000円と5,000円は抽出でtransferに分類され、現状のダッシュボードは支出と取引明細から除外する。画像の全出金額とダッシュボード支出額が違う場合はこの分類も確認し、取引の実態を確認せず変更しない。りそなの残高は画像にないため更新していない。画面の「確定」は画像が月の全件を網羅する証拠ではない。

銀行保存後に9月ページが404になったため、`lib/dataSource.ts` の銀行読み込みを未確定カードと同じキャッシュなしのPostgREST取得に修正した。ビルドと、モックで重複排除・残高null・失敗時フォールバックを検証し、mainへ反映後に本番表示を確認した。
